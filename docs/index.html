Quick Start

import { BodyChart, ViewSide } from '@emmorts/body-muscles';

const chart = new BodyChart(document.getElementById('container'), {
  view: ViewSide.FRONT,
  bodyState: {},
  onMuscleClick: (id, name) => {
    console.log(`Clicked: ${name} (${id})`);
  },
  onMuscleHover: (id) => {
    console.log('Hovered:', id);
  },
});

// Update body state
chart.update({
  bodyState: {
    'biceps-left': { intensity: 7, selected: true },
    'chest-upper-right': { intensity: 4, selected: false },
  }
});

// Switch to back view
chart.update({ view: ViewSide.BACK });

// Show both views side-by-side
chart.update({ view: ViewSide.BOTH });

// Cleanup when done
chart.destroy();

API Reference

new BodyChart(container, options)

Creates and mounts an interactive SVG body map inside the given DOM element. Optional fields set to undefined use their documented defaults; explicit false values are preserved.

Accessibility

The chart is a composite widget with a single tab stop: Tab enters on the first region and leaves in one step. Within the chart, ArrowRight/ArrowDown and ArrowLeft/ArrowUp move by one region, Home/End jump to the first/last region, Enter/Space activate the focused region, and Escape dismisses the tooltip. Each region is a toggle button whose pressed state tracks selected, and keyboard focus shows a high-contrast ring. Set interactive: false for a display-only chart announced as a single labelled graphic.

Verification covers keyboard interaction, Chromium's accessibility tree, and targeted automated audits. Screen-reader announcements and browse/focus-mode behavior remain unverified; these checks do not establish full WCAG conformance.

Instance Methods

Method Description
update(options) Merge partial options; undefined values are ignored. Changing view or interactive rebuilds the chart; every other change applies in place and preserves focus.
destroy() Remove the chart from the DOM and clean up all event listeners.

State Updates

update() merges the options object shallowly and ignores undefined values, but bodyState is replaced as a whole: a region omitted from the new mapping returns to its default (intensity 0, unselected). The chart never mutates the mapping you pass and keeps no selection state of its own. 

// Keep every other region and change one.
chart.update({ bodyState: { ...current, "biceps-left": { intensity: 7, selected: true } } });

// Apply a patch built elsewhere to the current mapping.
chart.update({ bodyState: { ...current, ...patch } });

// Remove one region's state.
const { "biceps-left": removed, ...rest } = current;
chart.update({ bodyState: rest });

There is deliberately no separate patch method: a spread expresses both preservation and removal, and a second entry point with different merge rules would only make the two easy to mix up.

Intensity Values

An intensity is a finite integer from 0 to 10. createBodyPartState(), the constructor, and update() enforce that rule and throw a descriptive Error for fractions, negative numbers, values above 10, NaN, or infinities. Validation runs before anything is applied, so a rejected update() leaves the chart exactly as it was. The colour helpers never throw — they round and clamp into 0-10, because they also render mappings a consumer mutated after the chart accepted them. 

isValidIntensity(9);   // true
isValidIntensity(9.5); // false

// Invalid bodyState entry for "biceps-left": intensity 12. Expected an integer from 0 to 10.
chart.update({ bodyState: { "biceps-left": { intensity: 12, selected: true } } });

Localization

Every rendered string comes from the labels option; each member is optional and falls back to English. The dedicated option wins over the matching member, which wins over the default: ariaLabel beats labels.chart, and tooltipFormatter beats labels.tooltip. Like bodyState, labels is replaced as a whole by update() — spread the current set to change one member — and label updates apply in place without rebuilding the chart or dropping focus. Explicit label updates refresh every label even when the same object is mutated and reused. Region and tooltip callbacks receive undefined state for omitted regions, or the supplied state object for tracked regions, including explicit intensity 0.

Anatomy Data & Terminology

The dataset describes regions of the body, not a muscle-by-muscle inventory: alongside individual muscles it contains areas such as head, face, nape, spine, and knee-left. Sides are the subject's own left and right (the anatomical convention), not the viewer's, so biceps-left is the subject's left arm and is drawn on the viewer's right. Regions without a side suffix are central. Canonical side and group metadata is available directly, so consumers never parse identifiers. 

MUSCLE_METADATA["biceps-left"];
// { id: "biceps-left", name: "Left Biceps", view: "FRONT", side: "left", group: "Arms" }

getMuscleMetadata(raw); // MuscleMetadata | undefined, for dynamic input

MUSCLE_GROUPS is the canonical group table, checked at compile time against the dataset and verified at build time to cover every region exactly once; MuscleGroup is the union of its keys. extractMuscleGroup(id) returns the identifier prefix ("biceps" for biceps-left), which is not the display group — use MUSCLE_METADATA[id].group for that.

Types

enum ViewSide {
  FRONT = "FRONT",
  BACK = "BACK",
  BOTH = "BOTH",
}

// Derived from the dataset: the union of every region identifier.
type MuscleId = "head" | "face" | "neck-left" | /* … 89 in total … */ "foot-back-right";

interface BodyPartState {
  intensity: number;  // 0-10
  selected: boolean;
}

type BodyState = Partial<Record<MuscleId, BodyPartState>>;

type IntensityColorResolver = (intensity: number) => string;

type MuscleSide = "left" | "right" | "central";
type MuscleGroup = keyof typeof MUSCLE_GROUPS;

interface MuscleMetadata {
  id: MuscleId;
  name: string;
  view: ViewSide;
  side: MuscleSide;  // the subject's own side
  group: MuscleGroup;
}

MuscleId is derived from the dataset, so state keys, callbacks, and helpers are checked at compile time and a misspelled literal is an error. Identifiers that only exist at runtime are not narrowed automatically: narrow them with isMuscleId(value) before using them as keys, or resolve them with getMuscleDef(id), which accepts any string and returns undefined when unknown.

MUSCLE_GROUPS Named groups: Head & Neck, Shoulders, Arms, Chest, Back, Abdominals, Legs, Hands & Feet

Data-Only Entry Points

Rendering the map without a DOM needs the anatomy data, not the chart. Import it from the dedicated subpath so the chart code and browser globals are never pulled in: @emmorts/body-muscles/data exports the same canonical values listed above, and @emmorts/body-muscles/data.json is the JSON document below for consumers that cannot run JavaScript at all. 

import { MUSCLE_MAP, MUSCLE_METADATA, INTENSITY_COLORS } from "@emmorts/body-muscles/data";

const { MUSCLE_MAP } = require("@emmorts/body-muscles/data"); // CommonJS

The JSON artifact carries a versioned schema — schemaVersion, plus intensityColors (11 CSS colours, index 0-10), frontMuscles, and backMuscles whose id, name, path, and view match MuscleDef. Additions keep the version; only a breaking shape change bumps it. Import attributes need Node 20.10+; the module subpaths work in Node 16+ and any modern bundler.

    Vanilla JavaScript

    <div id="body-map"></div>
<script src="https://unpkg.com/@emmorts/body-muscles/dist/umd/body-muscles.umd.min.js"></script>
<script>
  const { BodyChart, ViewSide } = BodyMuscles;

  const container = document.getElementById('body-map');
  if (!container) throw new Error('Missing #body-map element');

  const state = {};
  const chart = new BodyChart(container, {
    view: ViewSide.FRONT,
    bodyState: state,
    onMuscleClick(id) {
      const cur = state[id] || { intensity: 0, selected: false };
      state[id] = { ...cur, selected: !cur.selected };
      chart.update({ bodyState: state }); // bodyState replaces the whole mapping
    },
  });

  // Call chart.destroy() when removing this widget from the page.
  // Leave it mounted on navigation so back/forward-cache restoration works.
</script>

    React

    import { useEffect, useRef, useState } from 'react';
import { BodyChart, ViewSide } from '@emmorts/body-muscles';

export function BodyMap({ view = ViewSide.FRONT }) {
  const containerRef = useRef(null);
  const chartRef = useRef(null);
  const [bodyState, setBodyState] = useState({});

  // Props are read through a ref, so the instance effect depends only on `view`.
  const latest = useRef({ bodyState });
  latest.current = { bodyState };

  useEffect(() => {
    const container = containerRef.current;
    if (!container) return undefined;

    const chart = new BodyChart(container, {
      view,
      bodyState: latest.current.bodyState,
      onMuscleClick(id) {
        setBodyState(prev => ({
          ...prev,
          [id]: { intensity: prev[id]?.intensity ?? 0, selected: !prev[id]?.selected },
        }));
      },
    });
    chartRef.current = chart;

    // Unmounting, a changed `key`, or a view change destroys the chart and its
    // listeners; nothing is left behind.
    return () => {
      chart.destroy();
      chartRef.current = null;
    };
  }, [view]);

  // State and callback changes are applied in place, which preserves focus.
  useEffect(() => {
    chartRef.current?.update({ bodyState });
  }, [bodyState]);

  return <div ref={containerRef} />;
}

    The chart is constructed in an effect and never during render, so BodyMap is safe to server-render: the server emits an empty container and the chart appears after hydration. Give the component a key to force a clean remount; React 18+ development StrictMode double-invokes effects and the cleanup above handles that without leaking instances.

    Vue 3

    <template>
  <div ref="container" />
</template>

<script setup>
  import { ref, onMounted, onUnmounted, watch } from 'vue';
  import { BodyChart, ViewSide } from '@emmorts/body-muscles';

  const container = ref(null);
  const bodyState = ref({});
  let chart;

  onMounted(() => {
    if (!container.value) return;
    chart = new BodyChart(container.value, {
      view: ViewSide.FRONT,
      bodyState: bodyState.value,
      onMuscleClick(id) {
        const cur = bodyState.value[id] || { intensity: 0, selected: false };
        bodyState.value = { ...bodyState.value, [id]: { ...cur, selected: !cur.selected } };
      },
    });
  });

  watch(bodyState, (s) => chart?.update({ bodyState: s }), { deep: true });
  onUnmounted(() => chart?.destroy());
</script>
